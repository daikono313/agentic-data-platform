# フィードバックから改善する手順（#45 / #76）

画面で集まった評価から、インタビューのプロンプトを直す一周の手順。評価を付けるのはユーザー（人間）、集計と下書きはプログラム（要約だけ AI）、何を直すかを決めて eval のシナリオを書くのは開発者（人間）、プロンプトとコードを直すのは AI（Claude Code）。会話には実データが入るので、
**集計・下書きはローカルだけで扱い、リポジトリや PR には合成した内容しか入れない**（design-doc のプライバシー）。

## 1. 集める

- インタビューの発言ごとに 👍 / 👎（👎 は分類とコメント）、終わったらセッション全体を 5 段階で評価してもらう。
- 分類のうち「質問が重複している」「専門用語がわからない」「質問が長い・多い」「選択肢が合わない」は eval のチェックに
  対応している（`adp.evals.feedback.CATEGORY_CHECKS`）。これらは下書きのチェックに自動で入る。
  「何を聞かれているかわからない」「内容が間違っている」「その他」は対応するチェックが無く、人が会話を見て決める。
- 👎 を 👍 に付け替えると、👎 の理由（分類・コメント）は消える。

## 2. 集計する

```
make feedback-report            # .adp/reports/feedback-<日時>.md に保存
make feedback-report SUMMARY=1  # Claude による要約と改善案も（フィードバックが無ければ省く）
```

- プロンプトのバージョン別・段階別の 👎 の割合と、分類別の件数が出る。👎 の発言と、低評価（2 点以下）のセッションを見る。
- 高評価（4 点以上）のセッションのコメントは「直すときに壊さない点」として控える。
- `SUMMARY=1` では、このレポート（会話の抜粋と、低評価・高評価のコメント）を `adp.llm` 経由で Claude に
  渡す。インタビューと同じ送り先で、リポジトリや PR には入らない。

## 3. eval にする

```
make feedback-drafts            # .adp/eval-drafts/feedback_<session>.yml
```

- 下書きは実際の会話を元にしている。`request` と `persona` を**合成した内容に書き換えて**から
  `evals/interview/` に置く。分類が無い 👎 や、対応するチェックの無い分類も、会話を見て `checks` を決める。
- 0 件のときは、何をすれば下書きができるかを表示する（低評価がまだ無い）。

## 4. 直して比べる

1. 直す前に `make eval REPEAT=3`（結果は `.adp/evals/` に残る）
2. プロンプトを直し、`PROMPT_VERSION`（`backend/src/adp/interview/prompts.py`）を上げる。上げ忘れても
   バージョンには内容のハッシュが付くので比較はできるが、意図した変更は上げて区別する
3. 直した後に `make eval REPEAT=3`
4. `make eval-compare BEFORE=… AFTER=…` の結果を PR に貼る（certificate C10）

## 5. 確かめる

- マージ後、画面で集まる評価がプロンプトのバージョン別にどう変わったかを `make feedback-report` の
  「プロンプトのバージョン別」で見る。
